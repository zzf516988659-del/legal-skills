# 法律任务入口路由（legal-skill-router）

> 设计思想：致敬文格（lilialla/legal-document-format-skill）的"任务路由规则"：
> **"法律 AI 最怕任务入口混掉。明明用户只是想清理标点，结果模型开始重写内容。明明用户给了模板，结果模型从空白 Word 重新生成。明明只是格式定稿，结果模型顺手改了事实和请求。"**

## 一、定位

**法律任务入口路由 = 任务类型判定 + 路由到对应 skill**。

收到用户请求时，**第一步永远是判断任务类型**，**第二步才是调用对应 skill**。禁止"一步到位"。

## 二、任务类型与对应 skill

### 2.1 任务类型总表

| 任务类型 | 触发关键词 | 调用 skill | 输出物 |
|---|---|---|---|
| **A. 清理/格式化** | "清理标点"、"去 AI"、"格式化"、"标点全角" | `de-ai-polish` | 修复后的 Markdown |
| **B. 转 Word（单文件）** | "转 Word"、"出 DOCX"、"md2word" | `md2word` | DOCX |
| **C. 转 Word（带门禁）** | "转 Word" + "正式"、"对外"、"盖章" | `md2word` + `md2word-gate` | DOCX + 门禁报告 |
| **D. 模板生成** | "出 X 份律师函"、"批量出"、"按模板" | `contract-templates` | 多份 DOCX |
| **E. 合同审查** | "审查合同"、"审核合同"、"评审合同" | `contract-copilot`（3-Call 流水线）| 审查报告 + 修订版 |
| **F. 合同起草** | "起草合同"、"拟合同"、"写合同" | `contract-copilot` | 合同初稿 + 审查意见 |
| **G. 案件分析** | "分析案件"、"应诉策略"、"答辩思路" | `litigation-analysis` | 答辩状 + 质证意见 + 应诉策略 |
| **H. 法律服务方案** | "出方案"、"诉讼方案"、"咨询方案"、"建议书" | `legal-proposal-generator` | Markdown 法律服务方案 |
| **I. 法院短信处理** | "法院短信"、"传票"、"开庭通知" | `court-sms` | 归档 + 时间轴更新 + Cron 提醒 |
| **J. 法条检索** | "查法条"、"类案"、"找判例" | `yuandian-law-search` + `minimax-coding-plan-tool` | 法条 + 类案清单 |
| **K. 案件建档** | "新案"、"建档"、"开新案" | `new-case` | 12 目录标准结构 |
| **L. 微信文章抓取** | "抓微信文章"、"公众号文章" | `wechat-article-fetch` | Markdown |
| **M. OCR** | "识别扫描件"、"OCR"、"图片转文字" | `paddle-ocr` / `funasr-transcribe` | 文字 |
| **N. 法条格式化入库** | "法条入库"、"格式化法条"、"案例格式化" | `legal-text-format` | 格式化 Markdown |
| **O. 商标/专利** | "商标类别"、"专利分析"、"FTO" | `trademark-assistant` / `patent-analysis` | 商标/专利报告 |

### 2.2 混合任务拆分原则

很多请求是**混合任务**，必须**拆分为子任务**：

| 混合任务 | 拆分子任务 | 调用顺序 |
|---|---|---|
| "审查合同 + 出修订版 + 转 Word" | E → C | 1. contract-copilot 审查；2. md2word + gate 转 Word |
| "起草律师函 + 走门禁" | D → C | 1. contract-templates 模板生成；2. md2word + gate |
| "法院短信 + 案件分析" | I → G | 1. court-sms 归档建档；2. litigation-analysis 应诉 |
| "微信文章 + 入法律知识库" | L → N | 1. wechat-article-fetch 抓取；2. legal-text-format 格式化入库 |
| "审查合同 + 应诉策略" | E → G | 1. contract-copilot 审查；2. litigation-analysis 应诉 |
| "查类案 + 出咨询报告" | J → H | 1. yuandian-law-search 类案；2. legal-proposal-generator 报告 |

### 2.3 冲突优先级

| 冲突场景 | 优先级 |
|---|---|
| 用户说"方案"还是"建议书" | **用户原话**优先；不要自动降级 |
| 审查合同 vs 起草合同 | **用户原话**优先；不要自动转换 |
| 模板 vs 自由生成 | **如果用户说"按模板"或提供模板**→ 模板；否则自由生成 |
| 是否走门禁 | **正式/对外/盖章**→ 必须门禁；**内部讨论/草稿**→ 可跳过门禁 |
| 多个 skill 都能干 | **优先**用**最具体的 skill**，避免用通用 skill |

## 三、路由判别算法

### 3.1 输入

用户原始请求文本（可能很短，如"出律师函"，可能很长，如"分析这个合同并出修订版"）

### 3.2 算法步骤

```
Step 1: 关键词匹配 → 候选任务类型列表
Step 2: 上下文分析 → 任务组合（单任务/混合任务）
Step 3: 优先级判断 → 唯一执行路径
Step 4: 启动对应 skill → 按其内部流程执行
```

### 3.3 关键判断词

| 任务类型 | 强信号词 | 弱信号词 |
|---|---|---|
| 清理/格式化 | 清理、去 AI、全角、标点 | 修一下、改改 |
| 转 Word | 转 Word、DOCX、出文件 | 整理成 Word |
| 模板生成 | 律师函、催告函、批量 20 份 | 模板、出 X 份 |
| 合同审查 | 审查、审核、评审、找风险 | 这合同有问题吗 |
| 合同起草 | 起草、拟、写、帮我写 | 拟一份 |
| 案件分析 | 分析案件、应诉、答辩、诉讼策略 | 这案子怎么办 |
| 法律服务方案 | 出方案、方案书、建议书 | 帮我整理一下 |

## 四、典型场景

### 4.1 场景 1：单任务

用户："出 5 份律师函"

- 任务类型：D（模板生成）
- skill：contract-templates
- 输出：5 份律师函 DOCX

### 4.2 场景 2：混合任务

用户："审查这份合同，出个修订版"

- 任务类型：E（合同审查）+ C（转 Word）
- skill 顺序：contract-copilot → md2word → md2word-gate
- 输出：审查报告 + 修订版 DOCX（门禁通过）

### 4.3 场景 3：模糊请求

用户："整理一下这个"

- 不确定任务类型
- **必须先询问用户**：
  - 整理标点？→ A
  - 转 Word？→ B
  - 出律师函/报告？→ D/H
  - 归档？→ K

**禁止在不确定时自动猜测**——这正是文格要避免的"任务入口混掉"。

### 4.4 场景 4：诉讼全流程

用户："法院发传票了，我被告了，帮我处理"

- 任务类型：I（法院短信）+ G（案件分析）+ H（法律服务方案）
- skill 顺序：court-sms → litigation-analysis → legal-proposal-generator
- 输出：案件归档 + 应诉策略 + 客户方案
